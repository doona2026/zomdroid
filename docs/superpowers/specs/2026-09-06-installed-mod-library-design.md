# Mod 库已安装 Mod 增强设计

## 状态

设计已获批准；实现计划的全部任务已完成，主机侧验证通过，等待 MuMu/实机验证。


## 目标

增强现有 Mod 库页面，使其能够查看当前选定 Zomboid 实例实际安装的 Mod，同时保留现有共享 Mod 库归档及其安装、更新检查、分享和删除能力。

## 已确认的产品决策

- 实例选择器只作用于 Mod 库页面，不改变启动器的全局实例状态。
- 页面进入时、切换实例时、从其他页面返回时执行一次后台扫描；提供手动刷新按钮；不使用持续文件监听。
- 扫描实际目录 `<instance home>/Zomboid/mods`，覆盖 Workshop、手动安装、外部复制和未进入共享 Mod 库的 Mod。
- 从 `Zomboid/mods` 开始递归识别 Mod 根目录；目录自身包含根级 `mod.info` 时，该目录就是权威 Mod 根目录，不再继续识别其子目录中的 `mod.info`。只有没有根级 `mod.info` 的外层包装目录才继续递归，因此一个包内的多个独立 Mod 根目录仍分别显示为独立条目。
- 默认按 Mod 名称升序；可切换为最近修改或最早修改，时间使用 Mod 根目录的文件最后修改时间。
- 已安装 Mod 支持本地搜索，匹配名称、Mod ID、目录名和相对路径。
- 已安装 Mod 不增加启用/禁用、加载顺序或移动功能。
- 删除只作用于当前选定实例中当前条目对应的 Mod 根目录，不删除共享 Mod 库归档、其他实例或同级 Mod。
- 删除必须二次确认，弹窗显示 Mod 名称、实例名称和完整路径；成功后立即重新扫描并提示结果。
- 支持打开当前 Mod 根目录；无法定位时回退打开实例的 `Zomboid/mods` 目录。
- 本地详情显示 `mod.info` 解析结果、路径、大小和最后修改时间；能唯一匹配共享 Mod 库记录时提供 Workshop 详情入口。
- 缩略图只读取 `mod.info` 中的本地 `poster` 或 `icon` 文件；找不到或加载失败时使用统一默认 Mod 图标，不为列表扫描额外联网。
- 缺失或损坏的 `mod.info` 不影响其他条目：缺少名称时使用目录名，缺少 ID 时标记信息不完整；没有 `mod.info` 的普通目录不列入 Mod 列表，只计入忽略统计。
- 重复 Mod ID 不合并、不覆盖，分别显示并标记冲突。
- 页面顶部默认展开“当前实例已安装 Mod”，下方保留“共享 Mod 库”区域。
- 最近使用的实例选择只在 Mod 库页面记忆；实例失效时切换到第一个可用实例。
- 没有实例时显示空状态和“返回启动器”入口，不创建目录。

## 页面结构

```text
Mod 库
├─ 实例选择器
├─ 当前实例已安装 Mod
│  ├─ 实例名称 · 已安装 X 个 Mod · 忽略 Y 个未识别目录
│  ├─ 搜索框
│  ├─ 排序菜单：名称升序 / 最近修改 / 最早修改
│  ├─ 刷新按钮
│  └─ 已安装 Mod 列表
└─ 共享 Mod 库
   ├─ 说明
   ├─ 清理旧版本
   └─ 现有共享归档列表
```

已安装列表和共享归档列表使用独立容器、独立状态和独立动画，避免扫描或过滤操作清空现有共享归档。

## 扫描与领域模型

新增独立的已安装 Mod 扫描器/模型，不修改 `ModLibraryEntry` 的共享归档语义。

每个已安装条目至少包含：

- `instanceName`
- `rootPath`：规范化后的 Mod 根目录绝对路径
- `relativePath`：相对于实例 `Zomboid/mods` 的路径
- `name`
- `modId`
- `description`
- 本地缩略图路径（可空）
- `sizeBytes`
- `lastModifiedEpochMillis`
- `metadataComplete`
- `duplicateModId`
- 唯一匹配的 `publishedFileId`（可空）

扫描器从 `Zomboid/mods` 开始递归查找 Mod 根目录，并对同一根目录只产生一个条目。目录一旦存在根级 `mod.info`，其子目录视为该 Mod 的版本或子 Mod 内容，不再单独列出；无根级 `mod.info` 的包装目录才继续递归查找独立 Mod 根目录。解析 `mod.info` 时容忍空行、未知字段、编码异常和单个字段损坏；扫描失败只影响当前目录，不中断整棵目录扫描。目录大小在后台计算。

为防止实例切换后旧任务覆盖新结果，扫描任务带有请求序号或等价的取消/过期检查；只有当前实例且仍有效的扫描结果才能回主线程更新 UI。

排序和搜索只作用于内存中的当前扫描结果，不重新读盘。名称排序使用本地化无关的大小写折叠比较，名称相同再按 Mod ID 和相对路径稳定排序。修改时间排序使用根目录 `lastModified`，相同时间再按名称和路径稳定排序。

## Workshop 关联

匹配只使用本地已知数据，优先使用本地 Mod 库已保存的 Workshop 身份和归档根目录信息，其次使用归档内 `mod.info` 已解析出的 Mod ID。扫描当前实例时只考虑记录为安装到该实例的共享归档；外部复制的 Mod 只有在本地归档中存在相同 Mod ID 时才可关联。只有唯一匹配时才展示关联入口；无匹配或多候选时展示“未匹配”，不为每个已安装 Mod 自动发起网络请求。

关联成功后复用现有 Workshop 详情导航和数据入口；关联失败不影响本地详情页、搜索、排序或删除。

## 操作与安全边界

已安装 Mod 条目提供详情入口和更多菜单：

- 查看本地详情
- 查看关联的 Workshop 详情（仅唯一匹配时）
- 打开所在文件夹
- 删除

删除前校验目标路径仍位于当前实例的 `Zomboid/mods` 根目录下，且目标是当前扫描出的 Mod 根目录；拒绝路径穿越、根目录本身、实例外路径和无法确认的目标。删除成功后重新扫描当前实例；失败时保留条目并显示错误原因。

打开文件夹复用 `AppStorageProvider` 的 `DocumentsContract` URI。首先打开条目根目录；系统无法处理时打开 `Zomboid/mods` 目录，并提示完整路径。

## 状态与交互反馈

- 初次扫描：显示“正在扫描”状态。
- 扫描成功：显示实例名、已安装数量、忽略数量和结果更新时间。
- 空目录：显示当前实例未发现已安装 Mod。
- Mods 目录不存在：提示尚未创建 Mods 文件夹，并提供刷新。
- 扫描失败：保留上一次成功结果，显示错误原因和重试入口。
- 切换实例：立即进入新实例加载状态，丢弃旧实例过期结果。
- 删除成功：重新扫描并提示已删除的 Mod 名称。
- 删除失败：不移除列表条目，显示失败原因。
- 页面销毁时取消或忽略后台任务，避免回调访问已销毁 View。

## 非目标

- 不实现 Mod 启用/禁用。
- 不实现加载顺序管理或拖动排序。
- 不改变共享 Mod 库归档文件格式和已有下载/安装流程。
- 不建立独立的安装时间数据库；安装时间排序完全使用文件系统最后修改时间。
- 不为未知 Mod 自动批量联网搜索 Workshop。
- 不增加回收站、撤销删除或持续文件监听。

## 验收标准

1. 可在 Mod 库页面选择实例，并看到该实例 `Zomboid/mods` 中所有可识别 Mod。
2. Workshop、手动、外部复制和未进入共享库的 Mod 均能显示；根级 `mod.info` 下的嵌套版本/子 Mod 不重复显示；无根级元数据的包装包内多个独立根目录仍分别显示。
3. 名称升序为默认排序，可切换最近/最早修改；时间来自根目录最后修改时间。
4. 搜索能按名称、Mod ID、目录名和相对路径过滤。
5. 缺失/损坏元数据不会导致整页崩溃，并明确标记信息不完整。
6. 重复 Mod ID 分别保留并标记冲突。
7. 删除必须显示二次确认的 Mod 名称、实例和完整路径，且只能删除当前实例的对应根目录。
8. 可打开 Mod 所在目录；目录打开失败时有明确回退行为。
9. 唯一匹配的共享 Workshop 记录可进入现有详情页，未匹配 Mod 仍可查看本地详情。
10. 扫描在后台执行，切换实例或销毁页面不会出现旧结果覆盖、新 View 回调或崩溃。
11. 现有共享 Mod 库列表、清理旧版本、安装、更新检查、分享和删除行为保持不变。
