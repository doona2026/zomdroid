# Zomdroid Compose UI 全面重构设计

日期：2026-09-01

## 目标

将 Zomdroid 的所有管理界面从当前 XML/View + Java Fragment 体系迁移到 Kotlin + Jetpack Compose，并以 WorkshopAndroidDownloader 的 UI 组件和液态玻璃实现为基础，建立 Zomdroid 自己的统一 UI 架构。

这不是当前界面的换色或换皮。重构包含信息架构、导航、页面布局、交互反馈、状态管理、主题系统和响应式布局，同时保留现有游戏启动、安装、下载、存档、控制器、优化和 Workshop 能力。

## 已确认的产品决策

- 一级模块收敛为：启动器、Workshop、下载、模组库、设置。
- 启动器负责游戏实例、新建实例、启动和存档管理。
- Workshop 负责浏览、搜索、详情和 Steam 账号入口。
- 下载负责 Steam 下载、Workshop 下载中心和任务详情。
- 模组库负责已安装模组、版本、更新和导入。
- 设置负责渲染、控制器、优化、存储、日志、导入导出和帮助。
- 所有管理页面最终支持三种外观：液态玻璃、轻量液态、旧版经典。
- 外观切换立即生效并持久化。
- 首期完整支持简体中文、英语和俄语；葡萄牙语与印地语资源保留，但不作为首期完整验收范围。
- 支持手机竖屏、手机横屏和平板/大屏，并根据窗口宽度改变导航和内容布局。
- 游戏运行界面的 OpenGL 画面和游戏内触控覆盖层保持现有实现，不纳入应用外观切换。
- 所有管理页面、弹窗、控制编辑器和游戏启动前配置界面纳入 Compose 重构。
- 现有 Java 管理器、服务和底层功能通过 Adapter/Repository 继续复用，不把业务逻辑放进 Composable。

## 三种外观

三种外观是同一套 Compose 页面和状态架构下的三种渲染策略，不是三套互相独立的页面。

### 液态玻璃

- 使用程序化 Canvas 背景，而不是依赖网络或固定游戏图片。
- 使用分层 Backdrop：背景层、内容层和顶部/底部导航组合层。
- 使用 `backdrop` 的 blur、vibrancy、lens、高光、内阴影和外阴影绘制玻璃容器。
- 顶部导航、底部导航、弹窗、卡片和主要交互控件使用透明表面。
- 默认外观为液态玻璃。

### 轻量液态

- 保留液态模式的颜色、圆角、透明层级和布局语言。
- 减少或关闭高成本 blur、vibrancy 和复杂 Backdrop 绘制。
- 使用更实的 Surface、边框和低成本渐变，保证低端设备可用。
- 不改变用户选择；只有发生明确的渲染能力问题时才允许运行时降级。

### 旧版经典

- 使用 Compose 实现的实色背景、Material Surface、传统列表和经典导航。
- 不恢复当前 Zomdroid 的 XML 页面作为第三种外观。
- 仍使用与另外两种模式相同的页面状态、导航和文案资源。

## UI 架构

### 应用入口

在 Zomdroid 管理界面中建立 Compose 根入口，由应用级状态提供：

- 当前语言和深浅色主题；
- 当前前端外观模式；
- 当前一级导航；
- 全局 Snackbar/Toast/错误事件；
- 下载任务和全局服务状态。

`GameActivity` 继续保留独立的游戏渲染入口。控制编辑器可继续是独立 Activity，但其管理 UI 迁移到相同的 Compose Design System。

### 导航

使用 Compose 导航表达一级模块和详情层级：

- 手机竖屏：底部导航或抽屉；
- 手机横屏：侧边导航；
- 平板/大屏：固定导航栏，内容区域使用双栏或主从布局；
- 详情页使用统一返回行为；
- 深层页面不复制顶级导航逻辑。

原 Navigation Component 图和 XML menu 在迁移完成后删除或仅保留尚未迁移页面的临时兼容入口。

### 状态管理

每个一级模块使用独立的 Kotlin ViewModel + StateFlow：

- UI 只渲染不可变 UI State；
- 用户操作通过明确的 Action/Intent 进入 ViewModel；
- 下载、安装、存档和游戏实例通过 Repository/Adapter 调用现有服务；
- 页面旋转、进程恢复和返回栈由 ViewModel、SavedState 和持久化 Store 共同处理；
- 不在 Composable 中直接启动长期任务或持有业务对象。

Workshop 现有的状态流实现作为参考，并向其他模块推广，而不是把现有 Workshop 页面代码原样当作 Zomdroid 的最终信息架构。

## 页面迁移范围

### 启动器

- 游戏实例列表；
- 新建游戏实例；
- 游戏启动和启动前操作；
- 存档管理、备份、恢复和存储入口；
- 合并当前散落在菜单和弹窗中的实例操作。

### 设置与工具

- 通用设置；
- 渲染器、纹理缩放和 Java 参数；
- 控制编辑器入口；
- 游戏手柄映射；
- 触控控制设置；
- 优化；
- 安装控制、驱动、原生库和存档；
- 日志导出、错误报告和帮助/Wiki。

### Workshop 与下载

- Workshop 游戏入口、搜索、排序、分页和列表；
- Workshop 详情、评论、依赖和下载；
- Steam 账号、Guard 验证和账号切换；
- Steam 下载；
- 下载中心、任务详情、暂停、恢复、重试、取消、删除和日志；
- 模组库、版本记录、更新检查、多实例安装和备份。

## 代码移植与许可证

允许移植 WorkshopAndroidDownloader 的 Apache License 2.0 源码并进行修改，但必须：

- 保留源项目许可证、版权和归属信息；
- 对修改过的移植文件保留变更说明；
- 为 Zomdroid 补充第三方许可证/NOTICE 记录；
- 单独记录 `io.github.kyant0:backdrop` 和 `io.github.kyant0:shapes` 的依赖归属；
- 不复制 WorkshopAndroidDownloader 的业务文字、应用标识或与 Zomdroid 无关的数据模型。

## 迁移顺序

1. 添加 Compose 编译能力和最小运行依赖，建立主题令牌、外观模式、持久化和自绘背景基础。
2. 建立自适应根导航和全局弹窗/事件层。
3. 迁移启动器、游戏实例和新建实例，形成第一个完整可用的垂直切片。
4. 迁移设置、渲染、控制器、优化、存档和安装工具。
5. 迁移 Steam 下载、Workshop 浏览、详情和账号。
6. 迁移下载中心、任务详情、模组库和安装流程。
7. 迁移控制编辑器等特殊管理页面。
8. 为所有页面补齐三种外观、中文/英语/俄语、横竖屏和平板适配。
9. 删除已无调用的 XML 页面、旧导航和临时兼容代码。

迁移期间允许旧 XML 页面存在，但已迁移页面不得永久依赖旧页面或只支持一种外观。

## 非目标

- 不重写 Project Zomboid 的 OpenGL 游戏渲染；
- 不重写游戏内触控输入核心；
- 不删除现有功能或破坏已有数据格式；
- 不把 WorkshopAndroidDownloader 的整套应用入口、业务流程或文案直接复制进 Zomdroid；
- 不首期扩展到新的 Steam 游戏安装适配；
- 不首期恢复葡萄牙语和印地语的新页面翻译。

## 验收标准

- `:app:assembleDebug`、相关 Kotlin/Java 编译和单元测试通过；
- 所有管理页面可进入、返回和恢复状态；
- 现有游戏启动、安装、下载、存档、控制器和 Workshop 功能无回归；
- 每个管理页面支持三种外观，切换立即生效并在重启后保持；
- 液态玻璃使用程序化背景和分层 Backdrop，轻量液态能在低成本路径运行，经典模式不依赖玻璃效果；
- 中文、英语和俄语无新增硬编码文案；
- 手机竖屏、横屏和平板布局可用；
- 关键一级模块和三种外观有 Compose UI 测试或截图回归验证；
- 第三方许可证和移植归属信息完整；
- GameActivity 游戏画面与触控覆盖层行为不受影响。

## 主要风险

- Zomdroid 当前使用 Java 11，而 WorkshopAndroidDownloader UI 工程使用 Java/Kotlin 17；需要确认 Compose 与液态依赖在 Zomdroid 的 Java 11/Kotlin target 约束下可用，必要时只提高 UI 编译 target，不影响现有 native/Java 逻辑。
- 现有 Fragment 直接操作 View 并持有异步回调，迁移前需要逐模块识别状态和生命周期边界。
- Backdrop 效果可能受到设备 GPU、系统版本和窗口合成能力影响；必须保留轻量和经典路径，并进行 API 30+ 验证。
- 全量页面重构周期较长，必须以可运行垂直切片推进，不能一次性删除旧 XML。
- 当前工作区已有未提交的 Workshop 功能改动，UI 重构不得覆盖或回退这些改动。
